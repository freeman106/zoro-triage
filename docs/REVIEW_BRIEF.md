## 1. 한 줄 소개

> **신고 사진 한 장과 글 몇 줄이 들어오는 순간, Zoro-1이 0.3초 안에 "생명이 걸렸는가, 지금 번지고 있는가, 사진과 글이 맞는가"를 판정하고 상황판의 순서를 다시 세운다.**

재난 때 119 신고는 수백 건이 한꺼번에 몰립니다. 문자·앱으로 들어오는 사진 신고는 접수요원이 한 장씩 열어봐야 하고, 그 사이 더 급한 신고가 목록 아래에 묻힙니다. 이 에이전트는 사람보다 먼저 모든 신고를 훑어 우선순위를 매기고, **애매하거나 이상한 신고는 숨기지 않고 "확인 필요"로 위에 올립니다.** 최종 판단은 항상 사람이 합니다.

## 3. 왜 Zoro-1인가: 같은 조건에서 잰 근거

**System 1 설계: 한 번에 묻지 않고 쪼개서 묻는다.**
- 글에는 "진행 중인가, 위험한 사람이 있는가, 어떤 재난을 주장하는가"를 묻습니다.
- 사진에는 "피해가 심각한가, 현장 사진인가, 어떤 재난이 보이는가"를 묻습니다.
- 우선순위는 이 사실들로 정해진 규칙이 계산합니다. **Zoro는 사실을 판단하고, 우선순위 정책은 기관이 정하는 구조**라서, 기관이 규칙을 바꾸면 학습 없이 바로 반영됩니다.

합성 119 신고 400건(실제 재난 사진 + 생성한 한국어 신고 글, 정답은 규칙으로 계산) 기준입니다.

| 비교 (같은 지시문, 같은 L40S GPU) | Zoro-1 | Qwen2.5-VL-7B |
|---|---|---|
| 긴급도 정확도 (분해형) | **62.4%** | 33.7% |
| 1건 처리 중앙값 | **291 ms** | 1,213 ms |
| 사진 피해 필드 형식 오류 | **0 / 400** | 70 / 400 |

| 판단 구조 개선 | 정밀도 | 재현율 | 오경보 |
|---|---|---|---|
| 사진-글 불일치, 한 번에 묻기 | 29.8% | 100% | 229건 |
| **글·사진 따로 묻고 규칙으로 비교** | **100% (82/82)** | **84.5%** | **0건** |

- Zoro 세부 판단 정답률: 진행 중 96.8%, 위험 인원 87.5%, 사진 피해 62.0%
- 기준값은 학습용 500건으로만 정했고, 테스트 400건은 마지막에 한 번 채점했습니다(학습셋 정밀도는 96.6%).

## 4. 정직하게 밝히는 한계

- **합성 데이터 기준입니다.** 실제 119 신고에서의 성능은 측정하지 않았습니다.
- **학습된 전용 파이프라인보다는 낮습니다.** KcELECTRA+CLIP+규칙은 신고 라벨 50건(+사진 라벨 2,468장)만으로 68.0%였습니다. 그래서 제품 구조를 "라벨 0건인 1일차는 Zoro, 접수요원 수정이 라벨로 쌓이면 반복 판단은 전용 모델로 이전"으로 설계했습니다.
- **Qwen 비교 조건**: 지시문 조정과 출력 형식 강제(제약 디코딩)를 하지 않은 상태입니다.
- **사진 피해 판정(62%)이 병목**입니다. CrisisMMD 라벨 자체에도 노이즈가 있습니다(전용 CLIP 분류기도 71%).
- **현장 사진 판정**(포스터·합성·캡처 걸러내기)은 400건 중 35건을 비현장으로 표시했습니다. 정답률은 측정하지 않았고, 실제 현장 사진을 오판한 사례가 1건 확인됐습니다.
- **불일치 탐지 범위가 좁습니다.** 화재 대 비화재가 엇갈리는 경우만 잡고, 옛날 사진이나 다른 장소 사진은 못 잡습니다.

## 5. 검증 요청 항목

### A. 실행·재현
1. `cd demo119 && python -m unittest discover -s tests` 통과 여부
2. `proof.py`를 비어 있는 별도 인스턴스에 실행했을 때 `passed: true`와 위 수치(100건 시간, 폴백 0, 규칙 재판정, 403 권한)가 재현되는지. 사용법은 `demo119/README.md`의 "검증과 저장" 절에 있습니다.
3. 벤치마크 수치 재채점
   - 건별 예측: `bench/report119/results/*.jsonl`
   - 정답: `bench/report119/test119.json`
   - 불일치 분해형 예측은 인스턴스 `/ephemeral/crisis_bench/mismatch119-v1/test-predictions.jsonl`
   - 집계 기록: `bench/BENCHMARK_LOG.md`의 6절 이후

### B. 로직 검토 (`demo119/decision.py`)
1. 긴급도 규칙: 지난 일이면 비긴급, 진행 중이면 (위험 인원 + 심각한 사진 피해) 개수로 최우선/긴급/일반
   - **알려진 문제**: 생명 위협(의식 없음 등)이 사진 피해 없이 오면 "긴급"에 그칩니다. 글이 "지난 일"이면 사진에 불길이 보여도 비긴급이 됩니다. 정책 변경을 준비 중입니다.
2. "확인 필요" 조건: 핵심 판단 확률 0.35~0.65, 재난 종류 불일치, 현장 사진 확률 0.5 미만, 폴백
3. 폴백: Zoro 오류나 2초 초과 시 키워드 분류, 신고가 누락되지 않는지
4. 신고 하나당 Zoro 요청 4개(글 2, 사진 2)가 병렬로 나갑니다. 같은 사진이 두 번 인코딩되는 비효율이 있어 2개로 묶을 예정입니다.

### C. 보안·제출 위생
1. 신고용·상황판용 토큰 분리, 권한 없는 접근 403
2. 실제 토큰·사설 주소가 `.private/`(git 제외)에만 있고 저장소 파일에는 없는지
3. CrisisMMD(CC BY-NC-SA 4.0) 출처 표기, 원본 사진 미포함
4. 저장소는 로컬 git만 있고 커밋·push 전입니다.
