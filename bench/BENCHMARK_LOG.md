## 4. 진행 중이던 실험: 119 사진+글 신고 합성 테스트 (중단됨)

가설: 학습 데이터가 없는 판단, 그리고 답이 사진과 글의 관계에서 나오는 판단(긴급도, 사진-글 불일치)에서 Zoro가 강점.

설계 (`bench/report119/`)
- 사진: CrisisMMD damage 라벨 실제 사진 (train 이미지 → 학습셋, test 이미지 → 테스트셋, 겹침 없음)
- 글 사실(슬롯): 주장 재난, 위험 인원(none/at_risk/injured), 시점(now/past), 신고자, 말투, 지역
- 정답은 규칙으로 계산 (LLM이 정하지 않음):
  - urgency: past → non_urgent / 사람 위험 & 사진 심각 → top / 둘 중 하나 → urgent / 둘 다 아님 → normal
  - mismatch: 글의 재난군(fire/storm/quake) ≠ 사진 재난군 (fire ↔ 비fire만 섞음)
- `scenarios.json` 생성 완료: train 1,500 (불일치 319), test 400 (불일치 97; top 83, urgent 120, normal 46, non_urgent 54)
- 글 생성 규칙(합의): 피해 정도는 글에 쓰지 말 것(사진 몫), 사람·시점은 글에 분명히. 생성기는 Qwen 계열 금지.

결정 사항 (사용자)
- 신고 글 생성: 맥북에서 `claude -p --model haiku` 와 `codex exec -m gpt-6-luna` (싼 모델), scenario의 `generator` 필드로 반반 배정.
- 범용 VLM 비교 포함: Zoro `--mem-fraction` 0.8 → 0.45로 재시작함 (완료, `~/zoro-serve.sh`의 `ZORO_MEM_FRACTION` 기본 0.45). Qwen2.5-VL-7B-Instruct 다운로드 완료 (`/ephemeral/cache/huggingface`).

남은 단계
1. 신고 글 생성 (claude -p / codex exec, 배치 ~15건씩 JSON) → scenarios에 `text` 추가 → 인스턴스로 복사
2. Zoro: urgency choice(규칙을 기준 문장으로) + mismatch noul, 그리고 분해형(사람 위험/사진 심각/현재 진행 noul → 규칙) 두 방식
3. 비교: ① 다국어 CLIP(사진+글 임베딩) + MLP ② KcELECTRA 글 분류 + CLIP 사진 분류 + 규칙 ③ Qwen2.5-VL-7B 제로샷(같은 지시문, JSON 출력)
4. ①②는 학습 50/200/1500건 학습 곡선 → "Zoro = 학습 N건 모델 수준"
5. 결과 보고 (정확도, 불일치 탐지, 1건 처리 시간)

### 데이터와 실험 조건

- 맥북에서 Haiku와 gpt-6-luna가 각각 950건을 생성했다. 검사에서 발견한 재난 주장 누락, 물적 피해 묘사, 시점 충돌 등을 지정 생성기로 재작성했다. 일부 교정 문안은 지역명을 로컬에서 채웠다. 전수 검사는 슬롯 패턴 기준이며 사람이 1,900건의 의미를 전수 검수하지는 않았다.
- train 1,500건과 test 400건 사이에 동일 사진 ID·동일 글은 없다. 고유 사진은 각각 1,087장·336장이며 테스트 신고 24건은 학습 사진과 원본 게시물 ID가 같다. 실제 119 신고나 현장 긴급도 판단에서의 성능은 측정하지 않았다.
- 학습 세트는 고정 시드 42로 추출한 중첩 부분집합이다. MLP는 동결한 CLIP ViT-B/32 사진 임베딩과 이에 정렬된 다국어 문장 임베딩을 연결했다. 긴급도 헤드는 일치 예제만, 불일치 헤드는 전체를 학습했다. KcELECTRA는 글에서 위험 인원·시점·주장 재난군을 공동 미세조정했다. CLIP 사진 헤드는 모든 N에서 CrisisMMD train의 별도 라벨 2,468장으로 피해 심각도·재난군을 학습했다.
- Zoro 직접형은 사진+글 한 요청에 긴급도 choice와 불일치 noul을 묶었다. 분해형은 글 전용 요청(인원·시점), 사진 전용 요청(피해), 사진+글 요청(불일치)을 순차 호출했다. noul 임계값은 0.5다. Qwen은 직접형 질문·기준을 그대로 주고 JSON을 탐욕 디코딩했다(엄격 JSON·출력 제약 없음). 이미지 프로세서의 최대 픽셀은 448²으로 설정했다.
- 같은 L40S에서 워밍업 후 400건을 배치 1로 순차 측정했다. 이미지 로딩·전처리부터 예측 반환까지의 경과시간이며 Zoro에는 로컬 HTTP 비용이 포함된다. 직접형 시간은 Qwen 초기 적재와 겹친 첫 측정 대신 별도 단독 측정값을 사용했다. 서버는 mem-fraction 0.45를 유지했다.

## 7. Qwen 분해형을 추가한 동일 방식 비교 (2026-11-19)

직접형 두 모델의 정답 수는 모두 138/303이었다. Qwen은 일치 신고 303건 중 226건을 urgent로 예측했다. 분해형에서는 같은 질문과 긴급도 합성 규칙을 썼을 때 Zoro가 189건, Qwen이 102건을 맞혔다. Qwen 대비 Zoro의 건당 중앙 지연시간 비율은 직접형 1/2.17, 분해형 1/4.17이었다.

| 방식 | 모델 | 긴급도 정확도 | macro-F1 | 불일치 정밀도 / 재현율 | 건당 벤치마크 중앙값 |
|---|---|---:|---:|---:|---:|
| 직접형 | Zoro | 45.5% | .483 | 29.4% / 100% | 236 ms |
| 직접형 | Qwen | 45.5% | .358 | 양성 예측 0건 / 0% | 511 ms |
| 분해형 | Zoro | 62.4% | .626 | 29.8% / 100% | 291 ms |
| 분해형 | Qwen | 33.7% | .331 | 10.4% / 14.4% | 1,213 ms |

- **실행 조건**. 기존 Zoro 두 방식과 Qwen 직접형의 원시 예측을 재사용하고 Qwen 분해형만 추가 실행했다. 같은 L40S, 동일 테스트 ID 400개, 배치 1, 워밍업 2건이었다. 분해형 한 건은 글로 인원·시점, 사진으로 피해, 사진+글로 불일치를 묻는 세 호출의 전체 시간이다. 두 모델의 한국어 판단 지시문·입력 범위·긴급도 규칙은 같다. Zoro는 서버의 typed decision을, Qwen은 기존과 같은 로컬 Transformers BF16 탐욕 디코딩과 JSON 출력 지시를 사용했다(엄격 JSON·출력 제약 없음). 속도는 이 두 실행 구성에서의 측정값이다. 프롬프트 튜닝은 수행하지 않았다.
- **응답 형식 영향**. 표에서는 요청한 키의 최상위 JSON 불리언만 유효하게 처리했다. Qwen 분해형은 400건 중 201건에서 하나 이상 필드가 유효하지 않았다. 유효한 인원·시점·피해·불일치 필드는 각각 400·400·330·227건이다. 긴급도 채점 대상 303건에서 56건은 긴급도 산출이 불가능해 오답 처리했다. 이 56건을 전부 정답으로 가정한 상한도 158/303(52.1%)이다.
- **보조 채점**. 같은 원시 응답에서 요청 키 아래 명시적 answer/value/result/noul 불리언 또는 type 하나만 있는 불리언 객체를 추가로 읽었다. Qwen 분해형 긴급도는 115/303(38.0%), macro-F1 .348, 유효 긴급도 289/303이었다. 불일치 정밀도·재현율은 15.2%·28.9%였다. 형식 민감도를 보여주는 사후 분석이며 추가 추론은 없었다.
- **해석**. 직접형에서 Zoro의 확인된 장점은 시간과 macro-F1이다. 분해형에서는 이 지시문과 출력 방식에서 Zoro가 시간·긴급도 정확도 모두 앞섰다. 이 결과로 튜닝된 Qwen의 성능까지 추정할 수는 없다.

## 8. 불일치 질문을 글·사진 재난 종류로 분해 (2026-11-19)

질문과 판정 규칙은 평가 전에 고정했다. 글만 보고 fire / storm_flood / quake_collapse / other를, 사진만 보고 fire_smoke_burn / water_storm / collapse / unclear를 선택한다. 양쪽에서 선택한 클래스의 `probabilities[choice]`가 모두 공통 기준값 이상이고 화재 대 명시적인 비화재로 갈릴 때만 불일치를 표시한다. unclear, other, 지진 대 태풍 조합은 보류한다. 보류는 경고 미발생으로 집계했다.

## 10. 글·사진 요청 묶음과 생명 위협 정책 (2026-11-19)

## 11. 생명 위협 과판정 독립 검토와 채택 게이트 (2026-11-19)

**후보 문구는 미채택**. 사전에 test 생명 위협 재현율 ≥90% **및** 최우선 비율 ≤40%를 채택 조건으로 고정했다. 후보는 76.9%, 50.5%로 두 조건을 모두 충족하지 못했다. 운영 Zoro는 이전 생명 위협 질문과 0.50 기준을 유지한다. 따라서 고립·연락 두절의 모델 과판정은 여전히 한계다. 운영 정책에서 고립 자체는 위험 인원에 해당하고, 별도 생명 위협 양성, 사진 속 진행 위험 동반 또는 해당 운영 규칙이 최우선 승격 근거다.

사용자가 지정한 한국어 후보 질문을 기존 2요청의 글 묶음에서만 교체했다. `people_detail` 중 의식 없음, 숨을 잘 못 쉼, 사람 깔림, 다쳐서 피를 흘림의 네 슬롯을 양성으로 삼았다. ‘대피’의 ‘피’는 출혈에 포함하지 않았다. 이는 합성 슬롯 정답이며 의료적 위해도 라벨은 아니다. 시간 제한 없이 요청대로 매핑해 test 양성 117건 중 14건은 과거 사례다.

### 데모 반영

모델 오류 시 명시적인 호흡 정지·호흡 곤란·의식 없음·사람 깔림·심한 출혈을 키워드로 먼저 확인한다. 생명 위협이 명시되면 과거 표현이 섞여도 최우선+확인 필요다. 모델 확률은 null로 남긴다. 완료 목록은 사람 수정 등급을 우선한 유효 등급 → 같은 등급의 미검수 확인 필요 → 오래된 접수 순으로 정렬하고 분석 대기는 별도 띠로 보낸다. 모의 장애를 버튼에서 명시하고 규칙 변경은 폭주 전에 6건으로 시연한다. 폭주 중에는 실시간 경과시간을 표시하고 완료 시 서버 기록을 고정한다.

최종 실서버 검증은 `proof.py`의 `passed: true`로 완료됐다. 모의 장애는 ‘어제 사람이 쓰러져 의식이 없었다’는 합성 신고(test-0074)로 최우선+확인 필요였다. 폭주 전 카드 6건에서 고령자 고립 규칙을 추가하자 해당 카드가 긴급 5위 → 최우선 4위로 바뀌었다(1.06초). 이후 100건을 30.05초에 처리했고 폴백은 0건이었다. 인스턴스에서 접수→SSE 도착 4.17ms였고, 별도로 맥북의 모바일 뷰포트 Chromium에서 Tailscale 사설 주소로 사진을 제출해 클릭→상황판 대기 띠 414ms, 클릭→최우선 완료 목록 755ms를 관측했다. 이번 실행의 브라우저 측정은 실물 휴대폰의 카메라·통신 시간을 포함하지 않는다. ## 14. Zoro 서버 처리량 병목 진단과 서버 변경 (2026-11-20, Claude 세션)

**진단: 병목은 GPU가 아니라 Zoro 서버 프로세스의 CPU.** 같은 사진 요청을 동시에 1·4·8·16개 보내며 `nvidia-smi dmon`과 `top`을 함께 기록했다(`zoro_concurrency.py`).

- GPU 사용률은 측정 중 대부분 20~45%, 최고 79%. L40S 연산은 여유.
- Zoro 서버 본체 프로세스는 CPU 108~183%. 인스턴스 vCPU는 4개(g6e.xlarge). SGLang 스케줄러가 평소에도 코어 1개를 점유.
- 동시 요청을 늘려도 처리량이 초당 10건 안팎에서 정체되고, 요청당 시간이 동시 수에 비례해 늘었다.
- 원인 후보(코드 확인): `decide_engine.adecide`가 사진 디코딩·전처리·토큰화를 이벤트 루프에서 동기로 실행. `alogits`는 같은 사진을 질문·보기 수만큼(`image_data: [image] * len(prompts)`) 엔진에 넘김. SGLang에는 전처리 결과를 그대로 받는 `processor_output` 입력과 내용 기반 전처리 캐시(`mm_preprocess_cache_size_mb`, Qwen3-VL 계열 기본 0)가 있음. 둘 다 아직 미적용.

**변경 1: 메모리 비율 0.45 → 0.8 복귀** (Qwen-VL 비교 때 낮췄던 값). 효과는 측정 오차 수준(미리 줄인 사진 동시 8건 초당 10.9 → 13.0건).

- 판정 동일성: 고정 요청 28건(사진 24, 글 4)의 확률 최대 차이 0.0007. 같은 서버 반복 측정 노이즈 0.024보다 작음(`zoro_equiv.py`).

같은 가중치의 원문 → 잡음본 정확도다. 원문과 짝지은 잡음본은 사진·ID·정답이 같은 합성 신고 400건이다. 긴급도에는 이전 정책의 일치 신고 303건, 진행 중·위험 인원에는 전체 400건을 사용했다.

- 5개 스타일은 받아쓰기 오류 81건, 오타 84건, 사투리 66건, 끊어 보내기 79건, 짧은 신고 90건이다. 슬롯 키워드 검사에 표시된 36건(일치 신고 21건)도 포함했다. 기존 합성 정답을 유지했고 잡음 문장의 의미 보존을 사람이 전수 검수하지 않았다.
- 측정 시 GPU 가용량은 1,050 MiB였다. l40s-zoro-119의 격리된 CPU 환경에서 기존 학습 배치 16, 학습률·에포크 규칙·임베딩 및 분류기 구성을 유지했다. 표의 원문 값도 이번 재학습 결과다. 사진 CLIP은 CPU FP32로 추론했다. 횟수별 KcELECTRA 본체·토크나이저·3개 출력 헤드와 CLIP 사진·다국어 MLP 분류기를 저장하고 다시 읽어 양쪽 텍스트를 채점했다. 공개 동결 인코더의 정확한 리비전은 각 결과 JSON에 있다.

## 21. 사진 노이즈와 흐림에 대한 버전별 비교 (2026-11-20)

`main`의 이진 피해 판정(`579c5e4`, 0.50), 최신 3단계 피해 판정(`98d99c2`, 0.60), 개발 브랜치의 3단계 피해 판정과 Zoro-1 추론 검토(`89e3569`)를 같은 L40S의 `direct-checkpoint`에서 평가했다. `test119.json`에서 ID순으로 정렬한 뒤 시드 119로 합성 제보 100건을 뽑았다. 사진은 98장이고 심각 피해 라벨은 55건, 글과 사진의 불일치 라벨은 25건이다.

## 22. 사진 노이즈 평가의 대조 모델 비교 (2026-11-20)

21절의 합성 제보 100건과 사진 98장, 대조군·가우시안 노이즈·흐림 조건을 재사용했다. 데이터셋과 사진 입력 294개의 SHA-256을 기존 결과와 대조했다. 비교 모델은 Qwen2.5-VL-7B-Instruct-AWQ(`536a3579`, SGLang 0.5.23)와 InternVL3-2B-hf(`cb57a075`, BF16, Transformers 5.19.0)다. InternVL은 사진당 448px 타일 하나로 처리했다. [Qwen 모델 카드](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct-AWQ) · [InternVL 모델 카드](https://huggingface.co/OpenGVLab/InternVL3-2B-hf)

앱의 글 전용 3문항과 사진 전용 4문항을 같은 한국어 문구로 물었고, 제보 글의 응답은 세 사진 조건에 재사용했다. 자유형 JSON 시험에서는 두 모델 모두 유효한 심각 피해 필드가 0/300건이었다. 그 결과를 보존하고 동일한 문항·보기로 답을 알파벳 선택지에 제한해 다시 실행했다. Qwen은 SGLang 정규식, InternVL은 문항별 허용 토큰으로 출력을 제한했다. 두 실행 모두 탐욕 디코딩을 사용했다.

일반 LLM의 범주형 응답에 앱의 긴급도 규칙과 화재 대 비화재 불일치 규칙을 적용했다. Zoro의 확률 보정 문턱은 확률을 출력하는 Zoro 쪽에만 적용했다. 형식 오류로 심각 여부를 얻지 못한 건은 정확도 분모에 남겼다. 심각 피해 재현율은 정답 55건, 불일치 재현율은 정답 25건을 분모로 삼았다. 대조군 대비 긴급도 변화는 두 조건 모두 유효한 제보 쌍에서 셌다.

일반 LLM에는 불일치, 현장 사진 확인 불가, 과거 제보와 사진 속 진행 위험 중 하나가 표시된 제보에 확인 항목도 물었다. 이 지표에는 추가 응답의 완료와 항목 일치율을 기록했다. Zoro-1 추론 모드와 모델별 대상 선정 기준이 다르며, 확인 항목에는 독립 정답 라벨이 없다.

17절의 KcELECTRA+CLIP도 추가했다. 기존 가중치 파일을 확보할 수 없어 17절에 기록된 제보 1,500건의 학습 순서, 시드 42, 사전학습 리비전과 공식 피해 학습 사진 2,468장을 사용해 새 가중치를 만들었다. KcELECTRA는 L40S에서 네 에포크 동안 미세조정했고, CLIP은 CPU FP32로 추출한 고정 임베딩에 피해·재난군 로지스틱 회귀 헤드를 학습했다. 학습 사진과 전체 테스트 400건의 이미지 ID는 겹치지 않는다. 이 대조군의 긴급도는 17절의 규칙을 따르고, 불일치는 17절의 재난군 전체 비교와 화재 대 비화재 비교를 모두 기록했다.
